# lab 起点与步幅：先让它跑起来，一次只改一处

`layered-practice` §六 的五条内核（分步引导、亲手做、可验证、即时反馈、卡壳先引导）说的是**每一步长什么样**，
没说的是**第一步从哪开始**、**一步有多大**。缺了这两条，lab 最典型的两种失败是：起点是一堆空文件，学生
第一屏就要自己搭脚手架；或者任务写成「实现这三个功能」，一轮改三处，跑不过也分不清是哪一处。

本 ADR 定下三条：

1. **起点必须能跑**：任务目录给的起步代码要能启动、能跑出可见结果（功能不全没关系）。不是空文件，
   也不是编译报错的骨架。学生的第一个动作是「看到它跑起来」，第二个动作才是「改」。
2. **一次只改一处，5 分钟内看到结果**：每一步只动一个点。一轮改三处，错了就分不清是哪一处；
   而分不清原因，正是最容易让人放弃的时刻。
3. **划清与「干净态跑不过」的界限**：干净态（参考解还在答案目录、任务留白）跑不过是**断言失败**，
   那是留白有效的证据；起点跑不起来是 lab 的缺陷，不是证据。

`practice-evaluator` 同时点两处：时机一「出整套 lab 内容」与时机二「实验课的实操任务」都要求从骨架起、
起点可运行、单步只改一处——`rule-owners` 里 `practice-evaluator` 本就加载得到 `layered-practice`；这里的复述是为派工时上下文不足兜底，数字口径的唯一源头仍是 `layered-practice` §六（与 `14` 一样属允许的重复，不是第二个定义处）。

## Considered Options

- **只写「分步引导、任务留白」**：这是原来那五条，方向对但没给步幅口径，步与步之间可以差出十倍。
- **规定固定步数（如每课 5 步）**：内容长度差太多，写死步数会让简单任务被切成碎块、复杂任务被硬塞。
  选的是**按时间给步幅**（5 分钟内看到结果），不按步数。
- **让起点含完整功能、只留注释让学生「读懂」**：那就没有留白，也没有「亲手做」；起点必须是**功能不全但能跑**的。

## Consequences

- **「干净态跑不过」这句话被加了一处注解**：不改原句，只在它后面并列一句界限——这两件事混起来，
  会把能跑起来的 lab 判成缺陷，也会把跑不起来的起点当成留白有效的证据。
- **不动 `templates/lab/` 骨架**：起点能不能跑是**内容**要求，骨架已经给了跑法（干净态/作答态/自检），
  本章只要求作者把起点写成能跑的。
- **3 条 pin 落在 `RULES['layered-practice']` 末尾**：片段逐字取自 §六，措辞被改就会红。

这是 ADHD 适配方案（独立 docs 提交）四个功能 PR 里的第四个（PR 4），读法与边界见 ADR-0015。
